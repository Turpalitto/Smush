# SMUSH — AGENT EXECUTION CONTRACT (GLM / Codex / Claude)

> Положить в корень рядом с `SMUSH_MASTER_PLAN.md` и `SMUSH_ASSET_PIPELINE.md`. Это **операционный договор** для агента, а не отметка о выполненной работе.

## Кому что поручать

- **GLM:** художественные гипотезы, сцена Visual Lab, управление ассетами/шейдерами, визуальная A/B демонстрация. Не выполнять merge.
- **Codex:** независимое code review, безопасная интеграция одобренного стиля, регрессионные проверки, оптимизация/билды.
- **Claude или отдельный агент:** критика изображения, игрокоцентричный анализ, проверка читаемости и геймдизайна. Не быть единственным оценщиком собственного результата.
- **Владелец:** выбор художественного направления, разрешение на интеграцию, push/merge/release, ручной playtest.

## Обязательная дисциплина фаз

`PHASE 0 → PHASE 1 → PHASE 2 → PHASE 3 → PHASE 4 → PHASE 5 → PHASE 6 → PHASE 7 → PHASE 8`

На любом шаге:

1. Прочитай `SMUSH_MASTER_PLAN.md` и исходный код перед изменениями.
2. Сначала сформулируй фактический baseline и локальные задачи только данной фазы.
3. Признай имеющуюся работу (включая лабораторию GLM), не дублируй файлы/сцены.
4. Изменяй минимум файлов, держи исходный стиль доступным.
5. Подготовь **реальные кадры/видео**, тесты и сравнение. Не принимай собственную работу только по количеству тестов.
6. Не переходи дальше без **PASS** по текущему gate. Если требуется выбор владельца — статус `AWAITING_OWNER_DECISION` и не интегрируй.
7. Никакого автоматического `git push`, merge в main или выпуска APK в магазин. Для запуска CI-публикации ветки запросить разрешение.

## Стартовое поручение для GLM (скопировать целиком)

> Ты работаешь над `Turpalitto/Smush` (Godot 4.5) и обязан соблюдать файлы `SMUSH_MASTER_PLAN.md`, `SMUSH_ASSET_PIPELINE.md` и `SMUSH_AGENT_START.md`. Проверяй актуальный `main`, текущую feature-ветку GLM и существующие артефакты. На первом запуске сделай **только PHASE 0**, включая анализ существующего органического Visual Lab, 26 заявленных A/B пар, 2292 заявленных tests и ограничений security scan. Не воспринимай эти значения как проверенные без собственного воспроизведения. Создай `docs/production/00_BASELINE.md` с ссылками на реальные данные и заполни отчёт по шаблону. При PASS разрешается переходить к концептам **PHASE 1**, но **без изменения основной арены**. Отдельно зафиксируй визуальные проблемы по присланному скриншоту: слишком мелкая слизь в кадре, слабая биологическая морфология стадии 8, пёстрая земля, разнородность грибов/жуков/слизи, тяжёлый полноширинный HUD. Не менять всё сразу. Сначала нужно выбрать лучший новый образ одной слизи на стадии 8 и показать A/B/C в реальном масштабе. **Blender/генераторы использовать только если доступны и реально дают лучший результат**; не выдумывать исходники и рендеры. Создавай файлы только в рабочей ветке, не пушь, не мержь и не публикуй без разрешения владельца.

## Инциденты и запреты

- Ошибка `Camera2D` в экспериментальной сцене — отдельная регрессия для устранения; не игнорировать предупреждения без объяснения.
- `0 findings`, но `inconclusive` означает **не доказана безопасность**. Найденный позднее critical advisory в `web/` расследовать по отдельной security-задаче; не менять десятки зависимостей без идентификации пакета.
- Снимки A/B могут оказаться одинаковыми или содержать паузу: проверять **валидность сцены**, а не только числовую разницу пикселей.
- Настоящий Android GPU-тест нельзя заменить desktop-профилем.
- Не менять геймплейные формулы, чтобы красиво смотрелась картинка.
