# 2026-10-23 — environment art pass (commit 528cd72)

## What was built

- `tools/generate_floor_texture.py` — seamless 1024² moss floor tile, numpy + PIL only.
  Periodic by construction (wrapping value-noise lattice, modulo stamping). Measures its own
  seam: `0.0011` vs p99 interior step `0.0068` (ratio 0.19), exits non-zero if ratio > 1.
- `shaders/forest_canopy.gdshader` — UV → world pixels (floor scrolls under the camera), two
  samples of the same tile (1024 px and ×7) to kill the grid, luminance normalised against a
  baked mean (`FLOOR_TEXTURE_MEAN`) so it is a ±35% modulation, not a brightness shift.
  `floor_strength = 0` keeps the old gradient when the art is absent.
- `resources/art/props/*` — 5 FLUX props (root_pillar, rune_stone, mana_crystal,
  mushroom_cluster, fern_cluster) cut by the existing border flood fill, 256², mipmapped.
- `WorldGenerator` — `Sprite2D` per obstacle (width = radius × 2.45), pulsing halo behind
  crystals/monolith, squashed contact shadow, `_draw_prop_fallback()` if art missing; decor is
  weighted mushrooms 46% / moss 28% / fern 26%; arena edge = 3 staggered fern rows in its own
  `BorderHedge` node.
- `tools/quick_capture.gd` + `QuickCapture.tscn` — one frame of the real game in ~10 s
  (`QUICK_CAPTURE_STAGE=menu|arena`, `QUICK_CAPTURE_POS=x,y`, prints `App.state`).

## Bugs found (worth remembering)

1. **Inverted stamps.** `_smoothstep(e0, e1, x)` used `max(1e-6, e1-e0)` as the denominator, so
   with descending edges the mask flipped: every pebble/lichen dot stamped as a bright square
   with a hole. Looked like "digital camo" in-game. Fix: true `(x-e0)/(e1-e0)`.
2. **Texture scale.** A 1024 tile mapped to 420 world px = 2.4 texels per screen pixel → every
   detail aliased into squares. Set `floor_tile_px = 1024` (1:1) and made the fine detail
   coarser instead.
3. **Focus-loss pause.** The game auto-pauses on `NOTIFICATION_WM_WINDOW_FOCUS_OUT` (correct for
   mobile). Unattended captures and playthroughs froze mid-run. `quick_capture` reclaims focus
   and resumes; `GameManager` skips the auto-pause only when `PLAYTHROUGH_SUMMARY_PATH` is set.
4. `load()` inside `_draw()` per obstacle per frame → cached in `_prop_cache`.

## Floor relief + ray-traced AO (Blender pass, user offered "если что есть мсп блендер")

- The floor had a height field but only albedo was consumed. Added:
  - `tools/generate_floor_texture.py` now also writes `forest_floor_normal.png` (tangent-space,
    central differences through `np.roll` so the seam wraps) and a height map into
    `resources/art/environment/_source/` (a `.gdignore` folder — build input, never packed).
  - `tools/bake_floor_ao.py` — Blender 5.2.1 / Cycles. Height field becomes 9 tiled copies (3x3)
    so rays leaving the centre tile hit their own wrap-around neighbours; UV of the centre stays
    0..1, neighbours extrapolate outside. AO measured with the **Ambient Occlusion node** (explicit
    `Distance`) feeding emission, baked as EMIT — the built-in AO pass has no distance control.
    1.04M faces, 1024², 24 rays → 16 s on CPU. **Metal crashes the sandbox (exit 137)** → `--cpu`.
  - Shader takes `floor_normal` + `floor_ao`, each gated by its own uniform (`floor_relief`,
    `floor_occlusion`) so losing one map costs one layer only. Lambert is `dot(n,L)/L.z` so flat
    ground is exactly 1.0; AO is normalised on its own baked mean.
- **The real bug found on this pass was not the missing AO**: the tile measured 34 % relative
  contrast but *all* of it was in ~200 px patches, so at 1:1 the floor read as a smooth gradient.
  Added a high-frequency band (`clumps` ~20 px, `speck` ~10 px, `--grain 0.85`). Additive blending
  turned the tile into camouflage (it lifted dark soil as much as moss) → multiplicative with a
  bias below 1.0.
- Menu had to drop to `floor_strength 0.55` / `floor_tile_px 1400`: at full strength the grain
  competed with the title and buttons.
- AO/height alignment verified by correlation: 0.336 aligned vs 0.093/0.018/0.071 for v/u/both
  flips — so no UV flip is needed between Blender and Godot.
- QA **563 assertions, 0 failed**. Playthrough VICTORY 313.3 s, 64.9 HP, 85 absorptions, evo 5,

## Pass 7 — вершина лестницы и голос ступени (11-я итерация)

Главное: два дефекта, которые не видны ни в коде, ни в тестах, и оба про «заявлено, но не проверено».

1. **Порог вершины лестницы стоял выше потолка массы.** `MASS_KEYS[14] = 104`, а пики четырёх
   победных прогонов: 102.4 / 108.8 / 111.5 / 121.4. Слабейший не добирал 1.6 — корону видели
   не все. Порог 96, последние ступени сжаты. Тест требовал `≤ 128` (граница из комментария,
   не из замера) — теперь `≤ 100` и `≥ 85`.
   Массу держат два места: `MassSystem.SOFT_CAP_MASS = 78` (taper `1/(1+(m−78)·0.025)`) и
   дэш, сжигающий 1.5 % (`PlayerSlime.gd`, «tactical mass burn»). Поэтому пик гуляет 102–121.

2. **Звук роста перестал расти на 10-й ступени.** `AudioManager.play_sfx` зажимает
   `pitch_scale` в `[0.55, 1.75]`, а `0.82·2^((ступень−1)·1.5/12)` упирается в 1.75 ровно
   на десятой. Ступени 10–15 звучали одинаково. Заменил на 15 отдельных колоколов
   (`tools/generate_evolution_bells.py`, пентатоника C3–A5, 0.71 МБ, пик 0.58 как у старого).

Правило, которое стоит помнить: **если эффект «растёт по формуле», надо проверить, куда эта
формула упирается.** Оба дефекта — это clamp и порог, оба молчаливые.

Арт: третий заход по читаемости, на этот раз на 13–15 ступенях.
- `_veil` — цвет крупных форм, едет от яркости тела: белый при 44 % на тёмном, почти чёрный
  (v=0.16) при 92 % на светлом. Причина: 54 % среднего тона поверх среднего фона = та же
  яркость (0.34·0.54+0.35·0.46≈0.34), крыло было и не было.
- Ореол: тёмный контур МЕЖДУ свечением и ядром, иначе чистый свет на золотом мире ничем не
  определён.
- Шейдер: внутренняя деталь была аддитивной и белой → на кремовом теле пусто. Теперь
  `detail = mix(core, body*0.52, smoothstep(0.58,0.82,lum))` и полосы СМЕШИВАЮТСЯ к нему.

Инструменты: `PLAYTHROUGH_HEARTBEAT_SEC` (кривая массы), `growth_ladder_sheet.py` читает
`MASS_KEYS` из `EvolutionStages.gd` (была копия с комментарием «должно совпадать»).

## Pass 9 — биомы (блок 3) и стеклянный драфт (блок 4)

**Одна карта, два читателя.** Поле биомов живёт в одной RGBA-текстуре `64×64`, а не в
функции шума, написанной дважды (шейдер пола + CPU-тинт спрайтов). Две реализации одного
шума расходятся всегда, и расхождение читается как баг («роща мицелия на изумрудном полу»).
Правило шире биомов: всё, что обязано согласовываться по разные стороны границы рендера,
должно читать **один** ресурс.

**Сначала проверь инструмент, потом верь замеру.** Тест падал на «поле биомов
разрывно (max шаг 0.965)». Поле было гладким: контрастная рампа намеренно растягивает
каждый канал на `1/(0.68−0.32)`, поэтому легальный переход двух регионов проходит почти
весь диапазон за два-три текселя (на экране ~`640 px`). Проверил, повторив генератор на
Python для сида 424242: средний шаг `0.176`, p99 `0.895`, изолированных доминантных
текселей `5` из 4096. Заменил `max` на средний шаг + долю изолированных + число смен
доминанты на строку. **Max — плохой инструмент для поля с рампой контраста.**

**`ShaderMaterial.get_shader_parameter()` не отдаёт значение по умолчанию из шейдера** —
возвращает `null`, если параметр не выставляли. Тест упал на `assign Nil to Color`. Поэтому
`glass_tint` и `transmission` выставляются в `_ready` оверлея, а не живут только в шейдере.

**`set_parallel(true)` до `tween_interval` съедает задержку**: интервал попадает в ту же
параллельную группу, что и свойства, и все карточки летят синхронно. Правильный порядок —
`tween_interval` → первое свойство (последовательно) → `set_parallel(true)` → остальные.
Симптом невидим на успокоившемся кадре: увидел только телеметрией (`y=36.3, alpha=0.105` у
всех трёх). Тест теперь смотрит на **первый** кадр.

**Молоко стекла — не абсолютный подъём.** `blurred + 0.05` превращает каждый спрайт
свечения в серое облако: подъём абсолютный, а спрайты — самое яркое на экране. Работает
`mix(blurred, холодный серый, 0.42) · 0.82` (рассеяние теряет энергию) плюс `transmission`
как единственный регулятор «сколько мира видно».

**Размытие меряется парой кадров из одного запуска.** Два отдельных запуска дают разный
размер окна (ОС клампит запрошенный), и попиксельное сравнение между ними бессмысленно.
`QUICK_CAPTURE_PRE_OUT` пишет кадр до открытия оверлея в том же процессе.

**Читаемость — это число.** Контраст WCAG считается от цвета текста и карточки,
наложенной на *самую светлую* панель, которую стекло способно дать (`тинт·(1−t)+0.82·t`),
